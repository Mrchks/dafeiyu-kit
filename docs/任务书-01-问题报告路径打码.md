# 任务书 01：问题报告给用户名路径打码（双 AI 协作首次试运行）

- 派给：GPT（Codex）　　复核：Claude　　作者确认：是（2026-11-08）
- 写于：2026-11-08

## 目标
用户点「生成问题报告」后，压缩包里不再出现 Windows 用户名（例如 `C:\Users\<用户名>\...` 里的 `<Windows 用户名>`），发给别人看时不暴露真实用户名。

## 背景
- `docs/开发记录.md`「小白化（问题卡、问题报告）」一节：报告已去掉密钥、给 QQ 号和群号打码，但日志里仍有 `C:\Users\<用户名>` 这类路径。11-07 用户发来的报告里就有 `C:\Users\11145\...`。
- 打码逻辑在 `app/report.py` 的 `mask()`，报告由 `build()` 组装。

## 范围
- 要改：`app/report.py`；新增 `tests/test_report_mask.py`
- 不要碰：报告的文件结构和文件名、其他模块、作者的运行环境

## 要求
- 覆盖反斜杠和正斜杠两种写法（`C:\Users\名字\`、`C:/Users/名字/`），以及 JSON 里转义后的 `C:\\Users\\名字\\`。
- 用户名替换成固定的 `<用户>`，路径其余部分保留，方便判断问题位置。
- 当前电脑的用户名（`os.environ` 里的 USERNAME / USERPROFILE）如果出现在别处（例如单独出现在日志里），也一并替换。
- 不误伤普通文字：只处理路径和当前用户名。

## 验收标准
1. 新增测试覆盖上述三种路径写法、当前用户名单独出现、普通文字不被修改。
2. `python -m unittest discover tests` 全部通过。
3. 在作者电脑上实际生成一份问题报告，解压后全文搜索 `<Windows 用户名>` 无结果（Windows 上可用控制台「故障诊断 → 生成问题报告」）。
4. 记录：CHANGELOG「未发布 → 改进」加一条；`docs/开发记录.md` 相关章节更新；`docs/交接记录.md` 末尾追加一条。
5. 一次提交，提交说明以「问题报告：」开头。

## 交付
一次提交；交接记录写明提交号、验证情况和没做完的事。完成后由 Claude 按本任务书复核。
