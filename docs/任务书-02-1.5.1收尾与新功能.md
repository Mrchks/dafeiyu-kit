## 第一部分：页面加载与布局规范（全局）

### 现状
- `app/ui/index.html` 中没有骨架屏。各页面在切换后才发起请求，数据返回后直接写入 DOM。
- `p-chat`、`p-models`、`p-persona`、`p-backup` 四个页面没有 `fit` 类，内容超过一屏时整页滚动。作者反馈的典型问题：打开「模型与 API」约一秒后「已配置模型」突然出现，页面被撑长并变为可滚动。
- 页面内仍有原生 `<select>`（21 处，需确认是否都已被自定义下拉 `csel` 接管）和 `<details>`（2 处）。

### 要求
1. 所有页面改为一屏布局（`page fit`）：页头固定，内容区占满剩余高度；内容较多的列表、表格在自身区域内滚动，滚动区域上下边缘做渐隐。整页滚动只允许出现在窗口小于 1280×720 时。
2. 建立统一的加载约定并用于全部页面和窗口（总览、对话测试、常用设置、模型与 API、人设、知识库、记忆、用量与费用、日志、备份、版本与更新、安装向导各步、各类弹窗）：
   - 首次进入：显示与正式内容同尺寸、同结构的骨架屏（见样张第一页），数据返回后原位淡入，容器高度前后一致，不产生布局位移。
   - 再次进入：立即显示上一次的数据，同时在后台刷新，有变化才更新对应部分（沿用现有 `setHTML` 的「内容没变就不碰」做法）。不要每次切换都重新闪一次骨架。
   - 请求在 150 毫秒内返回时不显示骨架；骨架一旦显示，至少保持 300 毫秒，避免闪烁。
   - 读取失败：在内容区原位显示说明和「重试」按钮，不留空白，不弹自动消失的提示。
   - 没有数据：显示空状态说明和下一步操作入口（例如「尚未添加连接」加「添加连接」按钮）。
3. 按钮在请求进行中显示加载状态并锁定宽度，完成后恢复；不允许重复点击产生重复请求。
4. 内容出现一律带短促的淡入或位移动效（200–300 毫秒），不允许无过渡地突然出现；尊重 `prefers-reduced-motion`。
5. 定时刷新（总览每 3 秒一次等）不得引起可见的重排或闪动。
6. 清查原生控件：`<select>` 全部走自定义下拉；`<details>` 改为分页或固定区域；`title` 属性提示改为统一的悬浮提示组件（延迟约 200 毫秒，靠近边缘时自动换向）；`type=url` 等会触发浏览器校验气泡的输入改为自定义校验。
7. 弹窗统一：打开和关闭有动效，Esc 关闭，Enter 触发主按钮，打开时焦点落在第一个可操作项，高度固定。
8. 把以上约定写入 `app/ui/DESIGN.md`，作为之后所有页面的规范。

### 验收标准
1. 在 1280×720 窗口中逐页检查，没有任何页面出现整页滚动条。
2. 用浏览器开发者工具把网络调慢后逐页进入：每页先出现骨架，随后原位淡入；全过程页面高度不变。
3. 「模型与 API」页不再出现内容迟到后页面下沉的现象。
4. 断开控制台后端后进入各页：显示原位的失败说明和「重试」。
5. `index.html` 中不再有未被接管的原生下拉、`<details>` 和 `title` 提示。

## 第二部分：外观设置

### 现状
深色模式只通过 `@media (prefers-color-scheme: dark)` 跟随系统，没有界面开关。脑图的 `mapTheme()` 已把 `documentElement.dataset.theme` 计入缓存键。

### 要求
1. 「常用设置」增加「外观」一项，分段选项「跟随系统 / 浅色 / 深色」，默认跟随系统（样张第四页）。
2. 实现方式：`:root[data-theme="dark"]` 与 `:root[data-theme="light"]` 覆盖变量，`prefers-color-scheme` 的规则只在未指定主题时生效。设置保存在 `state.json`（经控制台接口写入），页面在首次绘制前就应用，不能先闪一下错误的主题。
3. 切换动效：整页交叉淡入（View Transitions API，时长约 0.4 秒；浏览器不支持时直接切换）。作者对样张第一版的评价是「切换有点生硬」，原因是各元素过渡不同步，因此要用整页过渡，不要逐元素过渡。
4. 一并适配：安装向导、托盘面板（`trayui.py`）、各弹窗、记忆脑图画布、图表。AstrBot 和 NapCat 的内嵌页面无法跟随，保持原样。
5. 深色模式逐页检查对比度、边框、阴影和状态色。

### 验收标准
1. 三个选项均可切换并立即生效，重启控制台后保持。
2. 系统为浅色时选「深色」、系统为深色时选「浅色」，都以所选为准。
3. 切换过程无闪白、无局部先变后变。
