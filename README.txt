大肥鱼整合包  v1.5.1
================================

将 DeepSeek 等大模型接入 QQ 的整合包。通过桌面控制台完成安装、配置和日常维护，bot 具备长期记忆，能够发送表情包和语音，并会主动发起聊天。

【开始使用】
1. 将压缩包完整解压到英文路径且不含空格的文件夹，例如 D:\Dafeiyu。
   请不要在压缩软件中直接双击运行，必须先完整解压。
2. 双击 START.vbs。
3. 在弹出的安装向导中按步骤操作，全程约 20–40 分钟，主要用于下载。
   中途关闭后，再次双击 START.vbs 会从中断的步骤继续。

安装完成后，桌面会出现「大肥鱼控制台」图标，屏幕右下角的托盘中会出现鱼形图标（绿色表示在线）。电脑开机后 bot 会自动上线。

【已在使用 AstrBot 和 NapCat】
如果本机已经在使用 AstrBot（启动器、源码或 pip 安装均可）和 Shell 版 NapCat，可以在安装向导的第一步选择「接入已有的 AstrBot 和 NapCat」，不必重新安装：
- 控制台会自动查找本机的安装位置，找不到时可以手动选择文件夹。接入时只记录位置，原有的人设、模型、插件和聊天记录不移动、不覆盖；会改动的配置文件先自动备份。
- 需要填写 AstrBot 后台的账号和密码；忘记密码时，可以选择「重设后台密码」。
- 大肥鱼插件组、大肥鱼人设、推荐的群聊和缓存设置都由自己勾选；推荐设置会逐项列出「当前值 → 推荐值」，确认的项目才会应用。
- AstrBot 需要 4.26.0 或更高版本。暂不支持 Docker 部署、非 Windows 系统和非 Shell 版的 NapCat，这些情况请选择全新安装，再用「备份与还原」迁移数据。
- 不再使用控制台时，在「版本与更新 → 卸载与许可」中点击「解除接入」：只移除控制台的桌面图标、开机自启和接入状态，原有的 AstrBot 和 NapCat 及其数据全部保留。

【需要准备】
- 一个 QQ 小号，以及已登录该小号的手机（用于扫码）。
- 主人自己常用的 QQ 号（作为 bot 的主人）。
- 一个模型服务商的 API Key（向导内置 12 家服务商预设，也支持自定义中转）。
- Windows 10 / 11，磁盘可用空间不少于 6GB。

【风险提示】
- 腾讯用户协议不允许使用第三方软件登录 QQ，也不允许以程序代替人工发送消息，小号存在被限制或封禁的风险。请只使用小号。
- 模型按用量计费，费用由所选的模型服务商收取。小额充值是控制支出上限的直接办法。
- API Key 和密码只保存在本机。

【知识库】
在控制台的「知识库」页新建知识库，上传 .md / .txt / .pdf / .docx 资料，再勾选需要启用的知识库并保存。此后群内问到相关内容时，bot 会先查询资料再回答。
每个知识库在整合包的「知识库」文件夹中都有一个同名文件夹，其中保存资料原稿。可以直接在文件夹中修改、添加或删除文件，然后在控制台点击「同步文件夹」。
主人通过私聊对 bot 说「记一下：……」时，资料类内容（规则、术语等）会记入知识库（保存在该文件夹的「主人补充.md」中，群内也可以查询）；主人本人的信息（学校、口味、习惯等）会记入记忆，只在私聊中召回。
群内遇到知识库中没有答案的问题时，bot 可以通过私聊询问主人；开关和每日次数上限在「知识库」页设置。
向量模型可以直接使用安装时配置的硅基流动记忆模型（免费）；未启用记忆时，请先在「AstrBot 管理后台」中添加一个 Embedding 模型。

【人设文件】
正在使用的人设保存在 AstrBot 数据库中，本地的 .md 文件只作为草稿。
在控制台的「人设」页，可以从 UTF-8 编码的 .md / .txt 文件导入正文，点击「保存」后生效；也可以导出当前编辑的正文。
只修改本地文件不会更新正在使用的人设。导出未保存的正文时，文件中保存的是草稿。

【记忆】
bot 每天凌晨将前一天的聊天整理为日记，并记录关于对方的稳定信息（档案）和带日期的事项（待跟进），每次回复时都会附带这些内容。
主人的档案由所有人设共用，日记按人设区分；群内无法读取主人私聊的内容。长时间未被提及的档案会逐渐淡忘，再次被提及时加深。
在控制台的「记忆」页，可以通过 2D / 3D 脑图查看记忆，修改或删除档案和日记，管理待跟进事项，预览每次回复附带的记忆，也可以点击「立即整理」。
待跟进事项到期当天傍晚，bot 会通过私聊询问主人；时间和开关可在 AstrBot 后台的「插件 → 大肥鱼记忆」中修改。

【版本与更新】
各版本的改动见 CHANGELOG.md，也可以在控制台的「版本与更新」页查看。
「版本与更新」页可以一键更新 AstrBot 和控制台；更新前自动备份，可以一键回退。NapCat 官方已停止发布新版本，控制台不再检查和更新 NapCat。请不要在 AstrBot 管理后台中点击更新，否则会与整合包的版本不一致。
电脑上安装了 Git for Windows 时，控制台会为每个版本保留一份记录，可以在「版本记录」中切换到旧版本，再返回最新版本；控制台无法打开时，双击「版本切换.bat」也可以切换。

【常见问题】
以下各项按「现象、原因、处理方法」说明。控制台出错时会显示相同的处理方法，可按提示操作；仍未解决时，请在控制台中点击「问题反馈」并附带问题报告（QQ 号、群号和密钥会自动隐去）。

■ 双击 START.vbs 没有反应
  原因：系统将 .vbs 文件关联到了其他程序。
  处理方法：右键 START.vbs →「打开方式」→「Microsoft Windows Based Script Host」。

■ 杀毒软件提示有风险，或文件丢失
  原因：杀毒软件将整合包中的脚本识别为可疑文件并隔离。整合包中只有脚本和官方 Python，AstrBot、NapCat 均从官方地址下载。
  处理方法：1. 打开杀毒软件的「隔离区」或「保护历史记录」，恢复被拦截的文件；2. 将整合包文件夹加入信任（排除项）；3. 返回控制台点击「重试」。

■ 安装 NapCat 时提示「下载的文件不完整」
  原因：NapCat 从 GitHub 下载，国内需要通过加速站；网络不稳定时文件只下载了一部分，解压会失败。与本机无关。
  处理方法：1. 点击「重试」，控制台会删除损坏的文件，并更换下载地址重新下载（最多自动重试三次）；2. 仍未解决时，更换网络后重试（例如使用手机热点）；3. 平时使用代理或加速器的，请开启后重试。

■ 安装 AstrBot 时长时间无进展，或提示「安装组件失败」
  原因：通常是国内软件源暂时无法连接，少数情况是磁盘空间不足。
  处理方法：1. 返回「安装位置与环境检查」步骤点击「检查」，确认网络和磁盘两项通过；2. 点击「重试」，控制台会自动更换软件源；3. 仍未解决时，请提交问题反馈。

■ bot 不回复消息
  原因：常见原因有四种：AstrBot 未运行、小号登录过期、模型余额不足、该群或用户不在白名单中。
  处理方法：在控制台「总览」页的「故障诊断」中点击「开始诊断」。每个问题下方都有对应的按钮（启动 AstrBot、扫码登录、前往充值、常用设置），点击后直接执行，完成后自动重新诊断。

■ 提示小号需要重新扫码
  原因：QQ 登录状态过期，或该账号在其他设备上登录过。
  处理方法：点击「扫码登录」，使用已登录小号的手机 QQ 摄像头扫码，并在手机上确认。截图无法用于扫码。

■ DeepSeek 余额不足或密钥无效
  原因：余额已用尽，或密钥被删除、复制时缺少字符。
  处理方法：余额不足时点击「前往充值」，充值后几分钟内恢复；密钥无效时，在 DeepSeek 密钥页新建密钥，并在「常用设置」中更换。

■ 更新整合包后，插件页面无法打开，或提示「重启 AstrBot」
  原因：部分改动需要 AstrBot 使用新设置重新启动一次后才能生效。
  处理方法：「更新内容」窗口中会列出「更新后的待办事项」，点击「重启 AstrBot」，完成后自动标记为已完成。重启期间 bot 约一分钟不回复消息。

■ 通过私聊让 bot 向群内发送消息，bot 表示无法发送
  原因：bot 不在该群内，或发出指令的人不是主人。
  处理方法：确认 bot 已加入该群，并且主人的 QQ 号已填入「常用设置」的管理员中。

■ 需要让 bot 在某个群停止发言
  处理方法：通过私聊对 bot 说「别在 XX 群说话」，或在群内让它停止发言，bot 会在该群静音；在群内发送「解除静音」即可恢复。也可以在「人设 → 会话分配」中开关。

■ 彻底卸载
  处理方法：在控制台「版本与更新 → 卸载与许可」中点击「完全卸载」，然后删除整合包文件夹。

【模型与识图】
在控制台「模型与 API」页点击「添加连接」，在窗口左侧选择服务商，填写 API Key 后点击「检测连接」。检测会直接请求服务商，在保存之前就能确认密钥是否有效，并列出可选的模型；思考程度用按钮选择。使用自定义中转时，在「高级」分页填写基础地址、接口协议和模型 ID。
保存连接前会对所选模型验证一次（会调用一次模型，产生极少量用量）。保存后在「用途分配」中将连接分配给默认聊天、识图或某个群、私聊；保存连接不会切换已有会话使用的模型。页面右上角的「配置说明」介绍了各服务商的密钥获取方式和检测结果的含义。
识图能力取决于具体型号，更换型号后请重新确认。所选的识图模型会同步用于群聊图片描述；普通图片不会套用万象棋识别规则。

【缓存与用量】
「用量与费用」页中，输入缓存占比 = 缓存输入 ÷（未缓存输入 + 缓存输入）。回复数可能包含多轮工具请求，也可能未计入接话判断、记忆整理和部分测试，因此不等同于完整账单。
固定的人设和规则放在提示的前段，变化的记忆和当前内容放在后段；同一会话持续使用同一模型，更有利于复用缓存。不必为了提高缓存命中率而保留无用的长内容。
缓存可以减少部分重复输入的计算和费用，但逻辑 token 数量仍会计入用量。各服务商的缓存门槛、有效时间和价格不同，费用以服务商账单为准。
